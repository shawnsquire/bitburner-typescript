# Code audit, 2026-09-19

Full pass over `src/` after the v3.0.1 API migration. Method: baseline checks
(tsc, eslint, contract harness, RAM checker), a new unit-test layer, then one
audit per subsystem verifying game-facing claims against the bitburner-src
checkout at tag v3.0.1. Per-system detail is in the sections below; the
consolidated fix list is in git history for this branch.

## Baseline before the audit

| Check | Result |
|---|---|
| `tsc --noEmit` | clean |
| eslint | 12 errors, 64 warnings |
| `npm run test:contracts` | 30/30 contract types pass |
| RAM checker | runs; no automated comparison against overrides or tier lists |
| Unit tests | none existed. The only tests were the contract harness and the RAM tool. |

## Infrastructure changes

- **Test runner**: vitest, `test/` tree, `vitest.config.ts` alias table, `test/helpers/mock-ns.ts`, `tsconfig.test.json`, `npm test` pipeline (typecheck, lint, build, unit, contracts). See `docs/development.md`.
- **RAM invariants as tests** (`test/tooling/ram.test.ts`): pinned scripts' `ramOverride` literals must cover static cost; tiered daemons must list every charged function. On first run this failed for 7 of 10 tiered daemons (blade, corp, faction, gang, rep, stocks, work); the per-system sections record what was missing.
- **eslint**: `no-constant-condition` now allows `while (true)` loops (the daemon idiom). Inferrable-type errors auto-fixed. Unused imports removed across 11 files.
- **Docs**: `docs/` created with architecture, development, per-system pages, and this report. README and CLAUDE.md link to it.

## Hack (daemons/hack, controllers/hack, lib/batch, workers, scripts/hack)

Tests: `test/lib/batch.test.ts` (22), `test/controllers/hack.test.ts` (14).

### [HIGH] Batch RAM math priced grow/weaken threads at hack.js's cost (lib/batch.ts, controllers/hack.ts)
- Grow and weaken cost 1.75 GB per thread, hack 1.70 GB (RamCostGenerator.ts). The planner used one price for all three, so tightly packed batches could exceed real capacity and the grow/weaken legs failed with pid 0, leaving targets unprepped.
- FIXED: `WorkerRamCosts` per op type through `calculateBatchThreads` and `allocateServersToBatchOps`; regression tests fail on the old behaviour.

### [HIGH] Stocks strategy never copied its workers to the fleet (daemons/hack.ts)
- `stock-grow.js` / `stock-hack.js` were exec'd on fleet hosts that did not have the files, so manipulation ran on home only.
- FIXED: scp step after allocation.

### [LOW] Dashboard hack plugin carried a dead legacy-only status computation (views/dashboard/tools/hack.tsx)
- First reported as HIGH ("batch, xp, drain panels unreachable"), then found to be dead code: the state store already reads `STATUS_PORTS.hack` and the panels were working. The stale computation and its ns imports were removed with the rest of the dead plugin fallbacks (see Dashboard section).

### [LOW] Fixed
- Dead duplicate `growThreads` call and `cores: 0` (should be 1) in batch thread math.
- Worker RAM header comments had the wrong arithmetic.
- Dead `cycleCount` in legacy mode; missing `?? 0` guard in network-monitor.

### Gameplay observations (not changed)
- `scripts/hack/simple.js` uses a multiplicative security threshold while everything else uses an additive buffer.
- Auto batch count is a flat 256 for any fleet at or above 256 GB.
- Pre-Formulas hack-chance uses current, not prepped, security.

## Work and focus (daemons/work, daemons/focus, controllers/work, controllers/crime, actions)

Tests: `test/controllers/crime.test.ts` (11), `test/controllers/work.test.ts` (24).

### [HIGH] Crime XP and karma rates ignored the on-failure award (controllers/crime.ts)
- The game grants 25 percent XP and a quarter of the karma on a failed crime (CrimeWork.ts). Rates were computed as success-only, which changes crime rankings for the karma and stats focuses.
- FIXED: expected value uses `chance + 0.25 * (1 - chance)` for XP and karma; money and kills stay success-only.

### [HIGH] Gym detection tested for the word "gym" in classType (daemons/work.ts, actions/check-work.ts)
- `getCurrentWork().classType` is `str`/`def`/`dex`/`agi` for gyms (Work/Enums.ts), so the published status always labelled gym training as university. Display only.
- FIXED: membership test against `GYM_STATS` in the daemon and the check action. The same test in the work plugin's fallback was dead code and has since been removed.

### [MEDIUM] classType-to-skill map had keys that never matched (controllers/work.ts)
- Worked only through the identity fallback. FIXED: map reduced to the two real translations (Algorithms, Leadership).

### [HIGH] assign-sleeve ignored the boolean result of every setTo* call (actions/assign-sleeve.ts)
- Failed assignments were toasted as success. FIXED: check the result, warn, fall back to idle.

### [HIGH] assign-sleeve chose gyms by the player's city, not the sleeve's (actions/assign-sleeve.ts)
- Sleeves have their own city and the game checks it. FIXED: reads `sleeve.getSleeve(i).city`.

### [HIGH] work daemon tier lists missed spawn and kill (daemons/work.ts)
- Found by the new RAM test. FIXED: added to `BASE_FUNCTIONS`; removed an unused `fileExists` entry.

### [HIGH] Tier 0 never called ramOverride (daemons/work.ts)
- Monitor mode stayed at the 5 GB placeholder while its real cost is about 15 GB, so its first `spawn` would have been killed. FIXED: override runs for every tier.

### [HIGH] Dashboard "Start Training" always started a Strength workout (views/dashboard/state-store.ts)
- Reported to the dashboard audit, which owns that file; see the Dashboard section.

### [LOW] Fixed
- Dead `focusHolder`/`sleeveHolder` parameters; stale RAM comment in check-work.

### Gameplay observations (not changed)
- `daemons/focus.js` reserves about 87 GB for life because of a one-time Simulacrum check; tiering it or moving the check into a short-lived action would free most of that.
- Only sleeve 0 is managed by the focus system.
- Sleeve assignment does not travel the sleeve and hard-codes hacking faction work and Homicide.

## Stocks, budget, hacknet (daemons/stocks, budget, hacknet; controllers/stocks, budget; lib/budget)

Tests: `test/controllers/stocks.test.ts` (48), `test/controllers/budget.test.ts` (18), `test/lib/budget.test.ts` (13).

### [CRITICAL] Stocks daemon could not launch under its tier system (daemons/stocks.ts)
- The game only honours a launch-time `ramOverride` when a numeric literal call is the first statement of `main`. The daemon computed its override, so it needed its full static 33 GB to start and the tier logic was unreachable. Also several charged functions (spawn, purchaseTixApi, purchase4SMarketDataTixApi, ps, kill, getScriptRam, fileExists, getPlayer, getServerMaxRam/UsedRam) were in no tier list.
- FIXED: literal `ramOverride(19)` first, `BASE_FUNCTIONS`, fallback-tier pattern as in hacknet; tier lists complete; RAM test passes.

### [CRITICAL] Pre-4S mode could never buy (controllers/stocks.ts, daemons/stocks.ts)
- Expected return was always 0 for moving-average signals, so the commission check always failed. FIXED; regression test added.

### [HIGH] Scraped volatility was 100x too large (actions/scrape-forecasts.ts)
- One scraper path returned percent where `getVolatility` returns a fraction. FIXED.

### [MEDIUM] Fixed
- Respawn-for-4S loop had no guard when the higher tier did not fit.
- Hacknet launch tolerance constant (5) did not match its 8 GB literal.
- Hash-spend accounting used a stale `hashCost` for non-money strategies.

### [LOW] Dead `calcDiversifiedBudget` and `HeldPosition` removed.

### Verified clean against the game source
- v3 TIX API needs no WSE account; API costs and 100k commission; hacknet functions cost 0.5 GB; short-selling probe order; behaviour without BitNode 9 or Source-File 9; budget-done protocol across all consumers.

### Gameplay observations (not changed)
- `wse-access` at 5 percent of cash deferred the 5b TIX API until 100b cash and 4S until 500b. FIXED with a one-off carve-out: the budget daemon grants the full price of the next API once cash is at least `wseCarveoutMult` (default 2) times it, so the APIs are bought at 10b and 50b. Weights are unchanged. See `docs/systems/budget.md`.
- The Budget tab does not display reported caps.
